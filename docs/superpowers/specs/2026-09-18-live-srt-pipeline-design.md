# Live SRT Contribution-to-Distribution Pipeline on AWS: Design

Date: 2026-09-18
Status: Implemented (v1); see the README

This document has two parts: a product part (PRD: what and why) and a technical part (TRD: how). A README is written after implementation.

---

# Part 1: PRD

## Purpose
A portfolio project, published as a Medium article and a GitHub repo, that demonstrates managing live broadcast cloud infrastructure with Terraform on AWS. It targets a Broadcast Cloud Engineer role (live sports host broadcast: SRT, AWS media services, Python automation, monitoring).

## Audience
Hiring managers and engineers in live broadcast and cloud infrastructure.

## Goals
1. Show a "stadium to screen" live path: SRT contribution in, ABR HLS distribution out.
2. Show infrastructure as code done properly: modules, remote state, tests, tagging, conventions.
3. Show Python automation for operating the workflow (start, stop, status, clean-check).
4. Show cost awareness: budget guardrails, short-lived demos, honest cost estimate.
5. Provide a concrete latency demonstration in the player.

## Success criteria
- `terraform apply` from a clean account state produces a working pipeline.
- An FFmpeg SRT source connects, and the stream plays in the hosted player page.
- The player shows the burn-in timecode next to the viewer's clock.
- `stop` and `terraform destroy` leave nothing billable running, confirmed by `check-clean`.
- `terraform test` passes without AWS credentials.
- Total spend for development and demos stays within the $25 budget.

## Out of scope (v1)
- Redundant (dual-pipeline) operation. The channel class is a variable, but the demo uses single pipeline.
- Monitoring, alarms and auto-remediation (candidate project #2).
- Multiple environments, CI pipelines, ad insertion, DRM, web UI.

## Constraints
- Personal AWS account, self-funded, $25 budget cap.
- Region: us-east-1 (chosen for cost and service availability).
- Author is new to Terraform and FFmpeg, comfortable with Python and prior SRT use.

# Part 2: TRD

## Architecture

```
FFmpeg (test pattern + burn-in wall-clock timecode)
   │  SRT caller, passphrase-encrypted
   ▼
MediaConnect flow (SRT listener, CIDR-whitelisted)
   ▼
MediaLive channel (single pipeline, ABR ladder 1080p/720p/480p)
   │  HLS
   ▼
MediaPackage v2 (HLS ingest, CDN authorization)
   ▼
CloudFront ──► static player page (S3 + CloudFront OAC, hls.js + latency overlay)
```

### Key decisions
- **MediaConnect as the ingest layer** (rather than SRT directly into MediaLive). It is the standard contribution-transport pattern and leaves room for extra outputs or a second source later. Direct SRT into MediaLive is documented in the article as a cheaper alternative.
- **MediaConnect is provisioned with the `awscc` provider** (`awscc_mediaconnect_flow`), because the `hashicorp/aws` provider has no MediaConnect flow resource. Everything else uses `hashicorp/aws`. The `ingest` module is the only one that uses `awscc`. If a spike shows `awscc` cannot create, connect and destroy the flow cleanly, the fallback is a `terraform_data` resource calling the AWS CLI.
- **Source thumbnails (requirement added 2026-09-18):** the flow enables MediaConnect source monitoring thumbnails (`source_monitoring_config = { thumbnail_state = "ENABLED" }` on `awscc_mediaconnect_flow`) so the incoming feed can be seen in the AWS console. It is exposed as an `ingest` module variable (default enabled). To verify in Plan 2: where the thumbnail appears in the console, whether it needs the flow to be active, and any added cost.
- **Delivery path (decided 2026-09-18, supersedes the earlier "MediaPackage v1" decision):** the goal is a fully declarative chain. Neither `aws` (6.65.0) nor `awscc` has a MediaPackage v1 origin endpoint resource, `aws_medialive_channel` has no CMAF-ingest output, and `awscc` has no MediaLive channel. So the path to try first is: MediaLive `hls_group_settings` (HLS output) → MediaPackage v2 with `input_type = "HLS"` (`awscc_mediapackagev2_*`) → CloudFront. Known risk: v2 ingest is authorized by SigV4/IAM channel policy, and MediaLive's generic HLS output has no SigV4 mode (CDN variants: Akamai, basic PUT, MediaStore, S3, WebDAV). It is spiked first (Plan 2). **If the spike fails, stop and ask the user before falling back** (candidates: MediaLive HLS → S3 → CloudFront, declarative; or MediaPackage v1 channel + `terraform_data`/AWS CLI for the endpoint).
- **Channel class is a variable**, defaulting to `SINGLE_PIPELINE`. The class is immutable after channel creation, so changing it replaces the channel. `STANDARD` also requires a second input and destination, and is not exercised in v1.
- **Ingest security:** SRT passphrase generated by Terraform and stored in Secrets Manager. The listener accepts only a configured source CIDR. The passphrase also lands in Terraform state, which is a known trade-off mitigated by a private, encrypted, versioned state bucket.
- **Delivery:** CloudFront fronts MediaPackage so the packager is not publicly open. The player page is served from a private S3 bucket via CloudFront OAC.
- **Latency overlay:** the page compares the burn-in wall-clock time with the browser clock. It is approximate (clock skew) and is presented as a demonstration, not a measurement.

## Repository layout

```
live-sports-aws/
├── bootstrap/        # one-time: S3 state bucket (local state)
├── modules/
│   ├── ingest/       # MediaConnect flow, SRT passphrase secret, CIDR whitelist
│   ├── encode/       # MediaLive input, channel, IAM role, channel_class variable
│   ├── medialive-role/ # IAM role that MediaLive assumes
│   ├── package/      # MediaPackage v2 channel, endpoint, CDN authorization
│   ├── delivery/     # CloudFront distribution, OAC
│   ├── player/       # S3 bucket + static page (hls.js + overlay)
│   └── guardrails/   # AWS Budgets + alerts
├── envs/demo/        # wires modules; variables; backend config
├── tools/            # livectl Python package (tools/livectl) and its tests (tools/tests)
├── source/           # FFmpeg script
├── scripts/          # price lookup for the cost estimate
└── README.md
```

Each module has `main.tf`, `variables.tf`, `outputs.tf` and `versions.tf`, follows the terraform-style-guide skill, pins provider versions, and applies consistent tags (`Project`, `Env`). Only the `demo` environment exists. Terraform tests live in each module's own `tests/` directory, because `terraform test` runs from the module folder.

Module contracts: `ingest` outputs the flow ARN and SRT endpoint; `encode` consumes the flow and outputs the channel ID and packaging destination; `package` outputs the HLS endpoint; `delivery` outputs the distribution domain; `player` consumes that domain.

## State
Remote state in an S3 bucket (versioning, encryption, public access blocked) created by `bootstrap/`. Locking uses S3 native lockfile (`use_lockfile`), so no DynamoDB table is needed.

## Python tooling (`tools/livectl`)
A small package using `boto3` and `argparse`, split into `targets`, `control`, `status`, `clean` and `cli`. Resource IDs come from `terraform output -json` by default and can be overridden with `--flow-arn` and `--channel-id` (then Terraform is not needed, which matters when state is unavailable).
- `start`: starts the MediaConnect flow, then the MediaLive channel, waiting for each to be running.
- `stop`: stops the channel, then the flow, waiting for both to be idle.
- `status`: prints flow and channel state, whether the SRT source is connected, the SRT endpoint and the playback URL.
- `check-clean`: exits 1 and lists any billable resources whose names start with the project prefix (channels in `DELETING` or `DELETED` state are ignored).

Commands are idempotent. Tests use `pytest` with `moto`; no AWS access is needed.

## FFmpeg source (`source/`)
A commented shell script wrapping one FFmpeg command: `testsrc2` plus tone, burned-in wall-clock time via `drawtext`, H.264/AAC, pushed over SRT with the passphrase and a configurable `latency`. Endpoint and passphrase come from environment variables.

## Testing
- `terraform fmt -check` and `terraform validate` on every module.
- `terraform test` with `.tftest.hcl` files, `command = plan` and mocked providers: channel class variable and validation, CIDR validation, tag propagation, module wiring. No AWS credentials needed.
- Python: `pytest` as above.
- End-to-end verification is the live demo itself.

## Cost controls
- AWS Budgets: $25 monthly, alerts at 50% and 80% (actual) and 100% (forecast), by email. It lives in `bootstrap/` so it survives `terraform destroy`. Alerts lag, so they are a safety net.
- Primary control is behavioural: `stop` and `terraform destroy` after each session, verified by `check-clean`.
- The cost estimate (`docs/cost-estimate.md`) is computed from the AWS Price List API and labelled as an estimate.

## Demo flow
`terraform apply` → `livectl start` → `source/send-srt.sh` → open the player page → `livectl stop` → `terraform destroy` → `livectl check-clean`.

## Verification tasks before implementation
These are facts to confirm against current AWS and provider documentation, not open design questions:
1. RESOLVED (spike passed 2026-09-18): no MediaConnect flow resource in `hashicorp/aws`; `awscc_mediaconnect_flow` creates an SRT listener flow with whitelist CIDR and `srt-password` decryption (do not set `algorithm`; MediaConnect rejects it for `srt-password`). A real FFmpeg SRT stream connected (`SourceConnected` = 1, about 2 Mbps), and `terraform destroy` left nothing behind.
2. RESOLVED: `aws_medialive_input` with `type = "MEDIACONNECT"` accepts `media_connect_flows { flow_arn }`.
3. RESOLVED (Plan 2 spike passed 2026-09-18): MediaLive `hls_group_settings` with `hls_basic_put_settings` PUT to a MediaPackage v2 channel (`input_type = "HLS"`, `awscc`) works, fully declarative. A SigV4-signed GET of the origin endpoint returned HTTP 200 with a 720p30 manifest and TS segments (decoded as H.264 1280x720 30 fps); MediaLive reported no 4xx/5xx output errors. The earlier prediction that the missing SigV4 mode would block this was wrong; the mechanism (role plus channel policy) was not verified. Notes: an empty `hls_basic_put_settings {}` block is dropped by the provider and rejected by MediaLive, so set retry values explicitly. Anonymous playback returned 403 even with a public-read endpoint policy, so Plan 3 must add CloudFront with MediaPackage CDN authorization. MediaConnect source thumbnails were confirmed visible in the console (Flow, Details, Preview).
4. RESOLVED: the S3 backend with `use_lockfile = true` works on the installed Terraform 1.16.3. The modules pin `>= 1.11` from my recollection that native locking became generally available in 1.11; I did not verify that floor independently.
5. RESOLVED (2026-09-18): see `docs/cost-estimate.md`, about 1.74 USD per hour for the priced items. Not priced: CloudFront data transfer out, and MediaPackage v2 live rates are assumed to equal the listed `EMP` ingest and packaging lines.
6. RESOLVED (cost): the Standard class is priced at about 1.67x the single-pipeline lines (for example HD output 0.7020 versus 0.4212 USD per hour), not 2x. The immutability of the channel class after creation is from AWS documentation as I remember it and was not tested.
7. RESOLVED: `moto` 5.2.3 supports MediaLive, MediaConnect and MediaPackage v2 create, start, stop, describe and list, which is all `livectl` needs.

If the `awscc` spike in item 1 fails, the fallback is a `terraform_data` resource calling the AWS CLI, documented in the article.

## Plan 3 result (2026-09-18)

Applied all 31 resources on the first try, streamed a 1080p SRT test source with a burned-in UTC clock, then destroyed everything with a clean leftover check.

- CDN authorization works as designed: direct requests to the MediaPackage v2 endpoint returned 403 with no header, 403 with a wrong `X-MediaPackageV2-CDNIdentifier`, and 200 with the correct one (a 404 appeared briefly while ingest warmed up).
- Through CloudFront: the player page returned 200, `config.json` carried the manifest path, and the master manifest returned 200 listing three renditions (1920x1080, 1280x720, 854x480).
- Not measured here: the glass-to-glass latency figure and browser playback details, which depend on the viewer's screenshot for the article.
- Deployment notes: CloudFront created in about 2.5 minutes; all module tests use mocked providers, with apply-mode mocks where computed values are needed.

## Risks

| Risk | Mitigation |
|---|---|
| `awscc` MediaConnect quirks (a reported apply that never finishes) | Spike first; CLI fallback |
| Forgotten running channel | Budget alerts, `check-clean`, destroy after every session |
| SRT connection issues (latency, firewall, passphrase) | Documented FFmpeg flags; `status` shows input connection state |
| Approximate latency overlay | Stated plainly in the article |
| Channel class immutable | Documented in the module |
| Passphrase in state | Private, encrypted, versioned state bucket; noted as trade-off |
